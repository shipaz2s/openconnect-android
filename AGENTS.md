# Инструкции по разработке

## Цель проекта

Добавить к Android-клиенту OpenConnect раздельное туннелирование по приложениям:
в профиль VPN можно включить режим, при котором через туннель проходит трафик
только выбранных Android-пакетов.

## Границы первого релиза

- Сохранить текущее поведение по умолчанию: без явного включения функции VPN
  обслуживает все приложения.
- Настройка должна храниться отдельно для каждого VPN-профиля.
- Единственная новая функция первого релиза — allowlist «только выбранные
  приложения». Когда функция выключена, сохраняется текущее поведение для всех
  приложений; отдельный расширенный набор режимов в MVP не нужен.
- Существующее раздельное туннелирование по IP-подсетям должно продолжать
  работать и комбинироваться с фильтрацией по приложениям.
- Не менять native-код OpenConnect и stoken без доказанной необходимости.
- Не добавлять `QUERY_ALL_PACKAGES` в MVP. На Android 11+ использовать
  ограниченную видимость launcher-приложений; возможность расширить список
  пакетов оставить на будущее.
- Сохранить `minSdk 23` и совместимость с Android 6. Не повышать минимальную
  версию Android без доказанной технической необходимости и согласования.

## Git-процесс

- Работать в отдельной feature-ветке от `main`.
- Перед началом этапа проверять `git status --short` и не затрагивать
  несвязанные изменения.
- Делать небольшие тематические коммиты: модель настроек, UI, применение
  allowlist, тесты/документация.
- Не переписывать опубликованную историю и не применять destructive-команды
  (`reset --hard`, принудительный push) без явного согласования.
- Перед каждым коммитом просматривать `git diff` и запускать доступные проверки.
- Не коммитить `local.properties`, ключи подписи, сертификаты пользователей,
  пароли, APK/AAB, каталоги сборки и IDE.

## Требования к реализации

- Использовать штатный `VpnService.Builder.addAllowedApplication()`.
- Добавлять allowlist до вызова `VpnService.Builder.establish()`.
- Не смешивать `addAllowedApplication()` и `addDisallowedApplication()` в одном
  экземпляре Builder.
- Включённый режим с пустым списком считать ошибкой конфигурации. Нельзя
  молча подключаться со всем трафиком: пустой Android allowlist означает VPN
  для всех приложений.
- Перед добавлением пакета проверять, что он установлен; исчезнувшие пакеты
  безопасно пропускать и отражать в журнале/интерфейсе.
- Изменение списка во время соединения применяется только после переподключения.
- Не включать пакет самого VPN-клиента в пользовательский список автоматически.
- Все новые пользовательские строки размещать в ресурсах. Обязательны английская
  и русская версии; отсутствие остальных переводов допустимо на первом этапе.

## Проверка

- Минимум перед интеграционным коммитом: сборка debug-варианта и lint.
- Логику чтения режима, проверки пустого списка и обработки отсутствующих
  пакетов покрывать локальными тестами, где это возможно без Android-устройства.
- Ручную проверку проводить минимум на Android 6 (minSdk) и на современной
  версии Android, соответствующей targetSdk.
- Проверять IPv4, IPv6 при доступности, DNS, переподключение, удаление выбранного
  приложения и совместную работу с маршрутами по подсетям.
- Результаты ручной проверки фиксировать в описании соответствующего коммита
  или в отдельном тестовом отчёте.

## Условие завершения

Работа не считается завершённой, пока сохранено прежнее поведение существующих
профилей, выбранные приложения используют VPN, невыбранные используют обычную
сеть, пустой список не приводит к утечке всего трафика в VPN, а проект проходит
согласованный набор автоматических и ручных проверок.
