# План: раздельное туннелирование по приложениям

Статус: согласован для MVP.

## 1. Цель и ожидаемое поведение

Добавить в каждый VPN-профиль опцию `Только выбранные приложения`. Когда она
выключена, сохраняется текущее поведение: VPN доступен всем приложениям. Когда
она включена, Android направляет в VPN только пакеты из сохранённого allowlist.
Другие варианты маршрутизации приложений в MVP не добавляются.

Фильтр приложений и существующий фильтр маршрутов работают одновременно.
Например, если выбран браузер, а VPN-профиль маршрутизирует только `10.0.0.0/8`,
только обращения этого браузера к `10.0.0.0/8` попадут в туннель.

Режим «все, кроме выбранных» (`addDisallowedApplication`) не входит в MVP. Его
можно добавить позднее без изменения формата allowlist.

Реализация сохраняет `minSdk 23` и поддержку Android 6. Используемый API
`addAllowedApplication()` доступен начиная с API 21, поэтому повышать
минимальную версию до Android 11 не требуется.

## 2. Техническая схема

### Хранение

В `SharedPreferences` конкретного `VpnProfile` добавить:

- boolean-флаг включения, например `app_routing_allowlist_enabled`;
- `StringSet` с package name, например `app_routing_packages`.

Существующие профили не содержат новых ключей и автоматически получают режим
с выключенной функцией, поэтому миграция данных им не нужна.

### Интерфейс

В редактор профиля добавить:

- переключатель `Только выбранные приложения`;
- пункт открытия экрана выбора приложений;
- краткое резюме с количеством выбранных пакетов;
- предупреждение о необходимости переподключения;
- ошибку при попытке использовать включённый, но пустой allowlist.

Экран выбора показывает доступные приложения с иконкой, названием, package name,
поиском и отметкой выбора. Список сортируется по локализованному названию.
Сохранённый, но уже удалённый пакет остаётся видимым как недоступный, чтобы
пользователь мог удалить его из настройки.

На первом этапе список видимых приложений следует получать через launcher-intent
и явно объявленный scoped `<queries>`. В MVP не добавляется
`QUERY_ALL_PACKAGES`: на Android 11+ selector показывает launcher-приложения,
но сама VPN-фильтрация остаётся поддерживаемой. Возможность расширить видимость
пакетов должна оставаться локальным изменением UI/manifest, не затрагивающим
VPN-логику.

### Применение

Непосредственно перед `establish()`:

1. Прочитать флаг включения и копию набора package name.
2. Если функция выключена, не вызывать методы per-app VPN.
3. Если функция включена, запретить подключение при пустом наборе.
4. Для каждого установленного пакета вызвать
   `VpnService.Builder.addAllowedApplication(packageName)`.
5. Отсутствующие пакеты записать в лог и пропустить.
6. Если после проверки не осталось ни одного установленного пакета, прервать
   подключение с понятной ошибкой, а не создавать VPN для всех приложений.

Фильтр должен настраиваться после создания Builder, но до единственного вызова
`establish()`. Native OpenConnect получает тот же TUN file descriptor и не
требует изменений.

## 3. Этапы разработки и Git-коммиты

### Этап A — воспроизводимая исходная сборка

- Разместить JDK 17 и Android SDK в проектно-локальном, игнорируемом каталоге
  `.devtools`, не изменяя системную Java и системный Android SDK.
- Написать воспроизводимый скрипт активации окружения с локальными
  `ANDROID_HOME`, `JAVA_HOME`, `GRADLE_USER_HOME` и `ANDROID_USER_HOME`.
- Восстановить отсутствующий в поставленном архиве Gradle launcher/wrapper.
- Проверить наличие Android SDK 35, build-tools и native-артефактов.
- Собрать неизменённый `assembleDebug` и запустить `lint`.
- Зафиксировать найденные исходные предупреждения отдельно от новой функции.

Предлагаемый коммит при необходимости:
`build: restore reproducible Gradle entrypoint`.

### Этап B — контракт настроек

- Добавить константы ключей, флага включения и набора пакетов.
- Добавить безопасное чтение настроек с выключенным значением по умолчанию.
- Вынести подготовку/валидацию allowlist в небольшую тестируемую единицу.
- Добавить тесты пустого, валидного и частично устаревшего списка.

Предлагаемый коммит:
`feat: add per-profile app routing configuration`.

### Этап C — выбор приложений

- Добавить ресурсы EN/RU и настройку режима.
- Реализовать экран списка приложений, поиск, сортировку и сохранение выбора.
- Показать количество выбранных и недоступные сохранённые пакеты.
- Использовать scoped package visibility для launcher-приложений.
- Не запрашивать `QUERY_ALL_PACKAGES` в MVP.
- Android TV selector отложить; телефонный интерфейс не должен ухудшить
  существующее подключение на TV.

Предлагаемый коммит:
`feat: add application allowlist selector`.

### Этап D — подключение к VpnService

- Применить allowlist к `VpnService.Builder`.
- Реализовать fail-closed для пустого/полностью устаревшего списка.
- Добавить диагностические сообщения без раскрытия чувствительных данных.
- Убедиться, что вызов выполняется до `establish()`.

Предлагаемый коммит:
`feat: route selected applications through VPN`.

### Этап E — стабилизация

- Пройти автоматическую и ручную матрицу.
- Исправлять обнаруженные дефекты отдельными понятными коммитами.
- Обновить пользовательское описание функции и ограничения.

Предлагаемый коммит:
`docs: document per-app VPN behavior and validation`.

## 4. План автоматической проверки

Обязательные команды после восстановления сборочного entrypoint:

```bash
./gradlew testDebugUnitTest --no-daemon
./gradlew lint --no-daemon
./gradlew assembleDebug --no-daemon
```

Проверить отдельно:

- новый профиль получает выключенный allowlist;
- старый профиль без новых ключей работает как раньше;
- включённый пустой allowlist отклоняется;
- установленные package name передаются Builder;
- отсутствующие пакеты не роняют сервис;
- полностью устаревший allowlist отклоняется;
- настройки разных VPN-профилей не смешиваются;
- поворот экрана/повторное открытие selector не теряет выбор.

## 5. Матрица ручной проверки

| Сценарий | Ожидаемый результат |
|---|---|
| Allowlist выключен | Поведение идентично исходной версии |
| Выбрано приложение A, B не выбрано | A использует VPN, B использует uplink |
| Allowlist пуст | Подключение не начинается, показана ошибка |
| Выбранный пакет удалён | Нет падения; пакет отмечен недоступным |
| Удалены все выбранные пакеты | Подключение безопасно отклонено |
| Список изменён при активном VPN | UI сообщает о ручном переподключении |
| Сервер прислал split routes | Allowlist и маршруты применяются совместно |
| VPN DNS | Выбранное приложение разрешает имена через VPN DNS |
| Uplink DNS | Сохраняется текущее поведение профиля |
| IPv4 default route | Только выбранное приложение идёт через VPN |
| IPv6 default route | Нет обхода allowlist через IPv6 |
| Quick Settings / повторный старт | Используется allowlist нужного профиля |
| Always-on без lockdown | Невыбранные приложения используют uplink |
| Always-on с lockdown | Показано предупреждение; проверено поведение ОС |

Для сетевой проверки использовать два приложения и сервис определения внешнего
IP, а также тестовый адрес во внутренней сети VPN. При возможности дополнительно
снять `adb logcat` и `adb shell dumpsys connectivity`.

## 6. Риски и решения

- **Пустой allowlist превращается во «все приложения».** Проверять список до
  `establish()` и прерывать подключение.
- **Ограниченная видимость пакетов Android 11+.** Начать с launcher-приложений;
  не использовать `QUERY_ALL_PACKAGES` в MVP; расширение видимости и политика
  Play Store — отдельное будущее решение.
- **Удалённые приложения.** Хранить package name, показывать stale-записи и
  пропускать их при формировании Builder.
- **Lockdown VPN.** Предупредить пользователя: ОС может лишить невыбранные
  приложения сети.
- **Старая UI-база (`android.preference`).** Реализовать функцию в текущем стеке,
  не совмещая её с миграцией на AndroidX.
- **Невоспроизводимая сборка архива.** Закрыть этот риск до изменения runtime-кода.
- **Различия Android 6 и Android 11+.** Per-app API доступен на всём диапазоне;
  отдельно тестировать selector до и после появления package visibility.

## 7. Критерии приёмки

- Исходные профили без настройки работают без изменения поведения.
- Allowlist сохраняется отдельно для каждого профиля.
- Через TUN проходят только выбранные и установленные приложения.
- Невыбранные приложения сохраняют прямой доступ к сети при отключённом lockdown.
- Пустой или полностью невалидный allowlist не включает VPN для всего устройства.
- Сетевые маршруты, DNS, IPv4/IPv6 и переподключение проверены по матрице.
- Debug APK собирается; unit tests и lint проходят либо исходные исключения
  документированы и не увеличены.

## 8. Согласованные ограничения MVP

- Новая функция только одна: VPN для выбранных приложений.
- `QUERY_ALL_PACKAGES` не используется; на Android 11+ показываются
  launcher-приложения в рамках scoped visibility.
- Поддержка Android TV selector отложена.
- Изменение списка при активном VPN требует ручного переподключения.
- Минимальная версия остаётся Android 6 (API 23).
- Окружение сборки размещается локально в проекте, без системной установки JDK
  и Android SDK.
